# v8：主划分上的两个训练对照

审稿意见要求的两个训练对照，在主划分（留出 F05、F08、F10、F13）上各跑 3 个种子，共 6 次训练。底座 Qwen3.5-35B-A3B，协议与 v2 完全相同（模型、LoRA、优化器、有效批量 64、微批 1、损失、检查点、贪心解码，`tests/test_v8.py` 检查），只改训练数据：

| 组 | 教什么 | 对照 |
|---|---|---|
| `A_multi` | 和 A_base 一样的 15,000 次动作曝光、同样的场景顺序，但每次的标签从该题带余量的可行集里随机取一个，而不是固定取位移最小的那个 | v2 的 A_base、A_compute |
| `A_cons_full` | A_base 的 15,000 次动作曝光，加上全部 29,400 条 consequence_v4 记录各一次（每个训练场景 6 个候选动作），是 v4 A_cons（按算力对齐，5,416 次）的 5.4 倍 | v4 的 A_cons，v2 的 A_base |

`A_multi` 在开发划分上做过（v5 m4_multi：拿掉 F09、F14 时留出族从 2.9% 升到 26.8%），这次在主划分上重复，回答“单标签规则对主划分的结论影响多大”。`A_cons_full` 回答“后果监督覆盖更多以后，后果判断和留出族成功率会不会改善”。

## 运行

先跑完 v7（`run_v7.sh` 会把 v7 增量包解进数据包；v8 的探针要用到它）。然后：

```bash
LOCUS_ROOT=/共享盘/项目目录 NODES=$LOCUS_ROOT/work/v8/nodes.txt nohup scripts/run_v8.sh > /dev/null 2>&1 &
```

- 步骤：核对环境和文件；单元测试；用真实处理器检查两种训练数据；训练 6 次（每个节点一次跑一个）；验证集选检查点（另报）；v2 整套测试题（每次训练和 B0，B0 与 v2 的 B0 对照，核对推理环境没变）；C1/C2；v7 的探针（S 题、改名题，A_cons_full 加后果探针）；打包。
- 时间：A_multi 每次约 25 分钟，A_cons_full 每次约 1–1.5 小时；8 个节点大约半天到一天。
- 中途停下，修好原因后运行同一条命令，已完成的步骤会跳过。
- 进度看 `$LOCUS_ROOT/work/v8/run_v8.log`。

## 打分（运行前写定）

主指标是测试集留出族（test_geometry）成功率，按场景重抽样给 95% 区间，同时报告已见族、留出组合、F13 和总分：

1. `A_multi` 对 A_base、A_compute 的差值；
2. `A_cons_full` 对 A_cons、A_base 的差值；后果探针（验证集和面板三个划分的平衡准确率、高度数值误差）对比 v4 A_cons 的 v7 探针结果。

两组都只报告数值和区间，不设“有效”门槛：它们是检验主结论稳不稳的对照，不是新方法。
