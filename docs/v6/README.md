# v6：最终测试（先想象再挪动）

v5 在开发集上比较了四种方法，“提出候选、想象结果、再选择”的微调阶段（v5 的 `m2_imagact`）最好：没训练过的两个族上从 2.94 提高到 29.85，三个种子都在 27.7–32.6。v6 用全部训练族重新训练这个方法，在冻结测试集上只测一次。

## 训练

- 方法 `A_imagine`（`configs/v6/A_imagine.yaml`）：答案先列 4 个候选挪法，各写出移动后的结果，再选出结果全部满足的那个。和 v5 的 `m2_imagact` 完全相同，只是不再留出 F09、F14；不接强化学习。
- 协议与 v2 相同：模型、LoRA、优化器、有效批量 64、微批 1、损失、检查点、贪心解码都不变（`tests/test_v6.py` 检查）。15000 次曝光，场景顺序和 v2 的 A_base 同种子完全一致（`run_v6.sh` 的 setup 用真实数据核对）。
- 3 个种子（0、1、2），终点检查点（ckpt-4）是预设评测点。
- 对照组直接用 v2 已经跑完的 A_base（同样 15000 次动作）和 A_compute（同训练量、只学动作），不重训。

## 判定标准（运行前写定）

沿用 v4 的标准，不做改动。主指标是测试集留出结构（test_geometry）上的成功率，三条同时满足才算有效：

1. 比 A_compute 至少高 5 个点，且按场景重抽样的 95% 区间下限大于 0；
2. 比 A_base 至少高 5 个点，且 95% 区间下限大于 0；
3. 3 个种子里至少 2 个同时高于这两个对照组的均值。

同时报告分布内（test_id）、组合（test_composition）、F13、总分、几何路线和后果面板。打分由基准方用冻结评分器完成（`score_round.py v6`），测试结果出来后不再改任何训练或评测设置。

## 运行

服务器上沿用 v5 的数据包和环境，不需要新的增量包。先更新代码（v5 留在服务器上的本地补丁不涉及本次改动的文件，可以直接更新），然后：

```bash
LOCUS_ROOT=/共享盘/项目目录 NODES=$LOCUS_ROOT/work/v6/nodes.txt nohup scripts/run_v6.sh > /dev/null 2>&1 &
```

- `NODES`：每行一个节点 IP，运行命令的节点也要写进去。给 3 个节点时 3 个种子并行训练（每个约 26 分钟），测试推理分到这些节点。不设置时全部在本节点依次运行。
- 步骤：核对文件和数据对齐、单元测试、用真实处理器检查全部 5053 条训练数据、训练、测试（3 个种子和 B0 各跑 v2 的整套测试题，批量 1）、打包。B0 和 v2 的 B0 是同一个模型，用来核对推理环境没有变。
- 中途停下，修好原因后运行同一条命令，已完成的步骤会跳过。
- 进度看 `$LOCUS_ROOT/work/v6/run_v6.log`，训练日志在 `work/logs/v6-A_imagine-s<种子>.log`。

## 发回

跑完把 `work/v6/locus-v6-results-<日期>.tar` 和同名 `.sha256` 发回基准方打分。包里有全部测试答案、训练记录和检查点的 sha256，不含权重；检查点先保留在服务器上。
