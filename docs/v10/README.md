# v10：先看清、再计算（随机结构上的几何监督）

前面各轮的诊断指向同一处：

- 从几何到动作这一步不必学。给真实几何，固定求解器在留出族上能解 97.5%；而微调网络在同样的几何下只有 21%。
- 网络自己读出的几何，在新结构上也会变差。

至今的几何监督都只来自 10 个训练族。v10 用随机摆放的场景训练"读几何"，动作交给求解器。要回答的问题是：几何监督的结构多样性能不能让这条路线迁移到留出族。

## 实验

**训练**：底座 Qwen3.5-35B-A3B，协议与 v2 完全相同（模型、LoRA、优化器、有效批量 64、微批 1、损失、检查点、贪心解码，由 `tests/test_v10.py` 检查）。每组 3 个种子，共 6 次。两组只训练几何答案，不训练动作。

| 组 | 训练数据 | 曝光 |
|---|---|---|
| `G_rand` | `geometry_rand_v10`：5,053 个随机结构场景。目标 1–3 人；遮挡物 0–4 个，形状是柱、墙、块或吊挂，60% 放在相机和某个目标的连线附近，其余随意放；场景整体旋转、两侧墙和天花板收拢的规则与训练族相同。物体名只用 10 个训练族的名词，不用任何族的布局函数，也不用留出族的四个名词。生成器在基准仓库的 `generator/random_structures.py`。 | 15,000 |
| `G_fam` | `geometry_sft_v2`：10 个训练族的 5,053 条几何记录，就是 v2 AG 用的几何数据。 | 15,000 |

两组的以下各项都相同：
- 题面（V0 题面加几何指令）；
- 答案格式；
- 看不见字段的缺省值（hidden-defaults-v1，用训练集的先验）；
- 记录数和曝光量。

唯一的区别是场景结构。

**测试**：每次训练的终点检查点（ckpt-4，预先写定，不按验证集挑选）跑两组题：
- 600 道测试题的几何题面 `test_geom_predict`（v7 增量包）；
- 120 个诊断场景的 `test_diagnostic_geom_predict`。

设置是贪心解码、关闭 thinking、批量 1、1024 token。

## 数据

增量包 `locus-bundle-v1.7.0-addon-v10.tar`，由基准方单独传过去，sha256 在服务器说明里。里面有：

`geometry_sft_v2`（v2 增量包）和 `test_geom_predict`（v7 增量包）已经在 v9 用的数据包里。

## 打分（运行前写定）

在基准方完成。固定求解器作用在预测的几何上，没法用的几何算失败。区间按场景重抽样（先对 3 个种子取平均），95% 百分位。

1. **主指标**：留出族上求解器的成功率，`G_rand − G_fam`。
2. **其余指标**：
   - 已见族、留出组合、总分；
   - 已见族减留出族的差距；
   - 与 v2 AG 的几何路线（同一题面，29.7%）和最好的直接动作方案（v8 Action, sampled labels，37.7%）比较；
   - 按族的成功率；
   - 逐字段的几何误差（目标和遮挡物的水平位置、尺寸、高度，房间），按划分报告。
3. **结构相似度**：报告随机场景和四个留出族之间的布局相似度（相机、目标、遮挡物的相对位置），说明随机数据有没有碰巧覆盖到留出族。
