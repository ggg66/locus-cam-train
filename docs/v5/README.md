# v5：方法开发（开发集上比较四种训练方法）

v4 的三种辅助监督都没有让动作迁移到没见过的结构。v5 在**开发集**上比较四种方法，选出最好的一种之后，再用全部训练族训练、在冻结测试集上只测一次（这一步的配置在选定方法后另写）。开发阶段不读取测试集。

## 开发集

从训练族里拿出 2 个族，在开发阶段不训练，当作“没见过的结构”来评测：

- 规则（在任何 v5 运行之前写定）：不参与组合留出的训练族（F09、F11、F12、F14）里，去掉最大的两个（F11、F12）。
- 结果：F09 柜间缝隙、F14 前后一列，共 794 个训练场景，配置在 `configs/v5/common.yaml` 的 `data.exclude_families`。
- 评测两组：`dev_heldfam`（这 794 个场景，主指标）和 `dev_seen`（验证集里其余族的 336 题，看已见结构有没有变差）。

## 四种方法

| 命令 | 方法 | 做法 | 配置 |
|---|---|---|---|
| `m1` | 强化学习，执行结果做奖励 | 从开发基线的第一个检查点（微调 25%）出发做 GRPO：每题采样 8 个答案，奖励查动作表（做对 1，约束部分满足最多 0.3，非法终点 0，没有有效动作 −0.5） | `m1_rl.yaml` |
| `m2` | 提出候选、想象结果、再选择 | 第一阶段微调：答案先列 4 个候选挪法，各写出移动后的结果（每个目标的高度占比、边距、被挡点数、落点数，以及五项约束），再选出结果全部满足的那个；第二阶段从第一个检查点做 GRPO，奖励 = 动作奖励 + 0.5 × 合法候选的想象正确率（选的动作必须在候选里才计） | `m2_imagact.yaml`、`m2_rl.yaml` |
| `m3` | 逆向想象 | 动作 15000 + 5000 条“给出移动后的画面，问是哪个平移得到的” | `m3_inverse.yaml` |
| `m4` | 多解标签 | 与基线同样的 15000 次动作曝光，但每次的目标从该题的稳健可行集里随机取一个，而不是固定取位移最小的那个 | `m4_multi.yaml` |

开发基线 `base` = 不含开发族的 A_base（动作 15000 次），所有方法都和它比。

## 设计上的几个决定

- **强化学习从微调 25% 的检查点出发**：最终检查点已把训练题练了约 3.5 遍，8 个采样几乎全对，组内奖励没有差别，GRPO 就没有学习信号。25% 时格式已经学会，训练题还没背下来。每一步记录“组内无差别”的比例（`flat_group_share`），可以直接看到这一点。
- **方法 2 想象的是几个候选的结果，而不只是自己要选的那个**：只想象自己选的动作，标准答案永远是“全部满足”，这段文字不含任何关于后果的信息，也影响不了选择。现在 4 个候选的结果各不相同，选择由结果决定；强化学习里，选的动作不在候选中、或动作无效时，想象不得分，非法终点的候选也不计分（这种结果一句话就能写对）。
- **采样不改分布**：温度 1、top-p 1、不截 top-k，训练的对数概率就是采样时的策略；每步只更新一次，没有 KL 项。
- **强化学习的优势不做标准差归一化**（`normalize_std: false`）：归一化会把一组里 0.01 的想象差异放大到和“做对与做错”一样大。现在优势就是奖励差，做对与否的权重自然最大。
- **想象奖励至少要 2 个合法候选**（`min_legal_candidates`）：否则模型可以退化成只写一个候选，比较的结构就没了。
- **起点也单独评测**：方法 1 和方法 2 的 25% 检查点也评测一次（`base_at_ckpt-1`、`m2_imagact_at_ckpt-1`），用来分清提升来自强化学习，还是只因为提前停止。
- **方法 2 的动作只占答案 token 的约 6%**：逐 token 平均的损失里选择的权重较小，主要靠强化学习阶段的动作奖励补上。这一点要看第一轮结果，必要时在开发集上调。
- **方法 3 是原理上最弱的一个**：逆向想象和动作仍是分开的两类样本，和 v4 没过线的辅助任务同一结构，只因为数据现成、成本低而保留。

## 数据

增量包 `locus-bundle-v1.7.0-addon-v5.tar`（约 80 MB），sha256 `694e7da35f500fa43b9f15ae546810f2b777d350d708a2272636373761fe361a`，由基准方单独传过去。内容：

| 文件 | 内容 |
|---|---|
| `training_exports/{train,validation}/imagact_v5.jsonl` | 方法 2 的微调数据（4 个候选加选择），5053 / 400 条 |
| `training_exports/{train,validation}/inverse_v5.jsonl` | 方法 3 的逆向想象数据，20153 / 1596 条（目标不在画面里的已去掉） |

只有训练和验证场景，没有测试数据。基准方已核对：方法 2 的标准答案在自己的动作表上想象全对、选中的候选正好是唯一可行的那个且位置均匀分布；方法 4 用到的 29034 个稳健动作全部可行。

## 运行

```bash
export LOCUS_ROOT=/共享盘/项目目录
```

第一次（会先做公共步骤：解包核对、单元测试、真实处理器检查、缩小模型冒烟、开发基线训练和评测）：

```bash
ADDON_TAR=$LOCUS_ROOT/data/locus-bundle-v1.7.0-addon-v5.tar ADDON_SHA256=694e7da35f500fa43b9f15ae546810f2b777d350d708a2272636373761fe361a nohup scripts/run_v5.sh m1 > /dev/null 2>&1 &
```

之后依次：

```bash
nohup scripts/run_v5.sh m2 > /dev/null 2>&1 &
```

```bash
nohup scripts/run_v5.sh m3 > /dev/null 2>&1 &
```

```bash
nohup scripts/run_v5.sh m4 > /dev/null 2>&1 &
```

- 默认 3 个种子（`SEEDS="0 1 2"`）。同一方法不同种子之间可差约 8 个点，只跑 1 个种子分不清方法好坏。
- 设置 `NODES=节点列表文件`（每行一个 IP，运行命令的节点也写进去）后，各种子分到不同节点并行训练，评测也分到这些节点；不设置时全部在本节点依次运行。
- 中途停下，修好原因后运行同一条命令即可，已完成的训练和评测会跳过；`REDO="smoke"` 可重做某个公共步骤。
- 进度看 `$LOCUS_ROOT/work/v5/run_m1.log` 等；训练日志在 `work/logs/v5-<运行>.log`，强化学习每步的奖励、成功率、想象准确率在 `work/runs/v5/<运行>/metrics.jsonl`。

## 结果

每个方法跑完都会更新 `$LOCUS_ROOT/work/v5/dev_summary.md`：每个方法在开发族（主指标）和已见族上的成功率、与 `base` 的差值和按场景重抽样的 95% 区间，以及基线在已见族和开发族之间的差距。这个差距要足够大，开发集才能代表“没见过的结构”；测试集上它约为 55 个点。把 `work/v5/` 和 `work/runs/v5/*/metrics.jsonl`、`run.json` 发回即可。

## 说明

- 开发阶段可以随意迭代（改剂量、奖励、步数），不需要写进论文；定版后用全部训练族重新训练、测试集只测一次，判定标准在那时写定。
- 强化学习部分（`scripts/train_grpo.py`）在本地只做过单元测试和处理器层面的检查；第一次在服务器上运行的冒烟步骤会用缩小模型把微调、GRPO、推理、打分完整走一遍，不通过就停下。
- 每一步 GRPO 为同策略单次更新，没有 KL 项和参考模型；LoRA dropout 在强化学习时关闭。
